# Quality gate, palier 1 (#2438)

The rule (zones, function cap, no zone may rise, PR size, review severity) is the AGENTS.md section
[Code quality — palier 1](../../AGENTS.md#code-quality--palier-1-hard-owner-decision-2026-11-18). The gate is an
**owner-mandated exception** to the [Bespoke guard admission](test-conventions.md#bespoke-guard-admission-hard-rule)
rule (owner decision 2026-11-18); a breach is a **blocking QUALITY finding**.

- **Where:** `CI guard battery` > `Check quality ratchet` (own lane of `ci-final-gate`, run on every PR: the size rule has no path filter), running
  [`check-quality-ratchet.ts`](../../packages/scripts-ts/src/check-quality-ratchet.ts) against
  [`quality-baseline.json`](../../packages/scripts-ts/src/quality-baseline.json). Both are CODEOWNED. Locally: commit, then
  `pnpm check:quality` (measures commits; base = merge-base with `origin/develop`, override `QUALITY_BASE=<sha>`).
- **Measurement:** `@coderot-ai/cli` 1.5.0 (version and one SHA-256 over every file of the installed package, Roslyn components and wasm included, are constants in the script; the gate refuses any other build, so overrides, patches and lockfile edits cannot swap it. The owner bumps it by changing `package.json`, `CODEROT_VERSION` and `CODEROT_TREE_SHA256` together, in a CODEOWNED PR), `analyze --since-commit HEAD` (local, nothing sent, never `coderot ci`;
  Elastic-2.0 allows internal use). Fails closed on an empty scan, one with no valid clone, an unparsed or invalid file, or a judged tracked file
  missing from it (coderot skips files with a line starting "generated by").
- **Baseline never rises:** compared with the file at the target tip (event base sha), the diff using the merge-base, schema-checked (missing or non-numeric value
  fails; an unreadable base, tree or blob fails, only a clean "path not in tree" means bootstrap). Waivers: `exceptions` entries (`path`, `name`, `reason`;
  `<anonymous>` is refused). The two owner labels are constants in the script, not editable in the baseline:
  `quality-baseline-exception` allows a raise and the first introduction, `size-exception` a large PR; set it,
  then edit the PR description so the label is re-read. The baseline check also runs in the merge queue, where there are no labels: a raise lands there only if the owner recorded it in `ownerApproved` (`<key>=<new value>` or `exception:<path>::<name>`, reviewed through CODEOWNERS; only approvals added by the PR count). Size runs on PRs and locally (`QUALITY_SIZE_EXCEPTION=1` locally mimics the owner label). Ratios are per 1000 SLOC: deleting simple code can raise a zone (owner exception). Known limits: a clone scan that is partial but still has valid clones cannot be detected (only an empty or invalid one fails); deleting a code line right after a function flags it; a function moved within its file counts as modified, and C# overloads share one waiver.
- **Tightening a palier:** a dedicated PR lowers values by hand from the figures `pnpm check:quality` prints on the base branch.
