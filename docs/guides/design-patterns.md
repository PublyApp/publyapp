# Design patterns in PublyApp

The rules themselves: [`docs/conventions/design-patterns.md`](../conventions/design-patterns.md) and
[`docs/conventions/solid.md`](../conventions/solid.md) (verbatim local copies of the shared rules from
radandevist/conventions).
The service/port split behind Adapter, Decorator, Proxy and Facade is
[`docs/guides/ports-and-adapters.md`](ports-and-adapters.md); read it first.
This page only maps the patterns onto PublyApp: what already follows, the known gaps, and the few places
where a sign is present. No problem, no pattern: a row below is a place to look, not a refactor to schedule.

## Already in PublyApp

| Pattern                        | Where (real file / type)                                                                                                                                                                                                                       | Note                                                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Adapter                        | `apps/api/Infrastructure/Messaging/Email/ResendEmailAdapter.cs` (`ResendEmailAdapter : IEmailSender`); `apps/api/Modules/Aggregators/Adapters/Zernio/ZernioAggregatorAdapter.cs`                                                                 | Resend and Zernio types stay inside the adapter.                                                          |
| Adapter                        | `packages/shared-ts/src/lib/logger/adapters/winston-logger-adapter.ts`, `stdout-json-logger-adapter.ts`                                                                                                                                        | One adapter per medium; the `Logger` service filters levels and redacts before the port.                   |
| Strategy                       | `apps/api/Modules/SocialAccounts/Adapters/SocialAdapterRegistry.cs`                                                                                                                                                                            | The registry indexes `ISocialPublisher` by network; the network is a key, not a `switch` in the job.       |
| Service layer (Facade role)    | `apps/api/Infrastructure/Messaging/Email/EmailService.cs`; `packages/shared-ts/src/lib/analytics/analytics.ts`                                                                                                                                  | One call owns render + send / consent + mask + send. The service plays the Facade role; do not add one on top. |
| Decorator                      | `apps/api/Lib/Logging/SanitizingLogEventSink.cs`; wiring in `apps/api/Lib/Logging/SanitizingSinkConfigurationExtensions.cs`                                                                                                                    | Wraps every durable sink as the process-wide redaction backstop; it is not a template for wrapping ports. |
| Proxy                          | `apps/api/Infrastructure/Storage/ReparsePointExclusionFileProvider.cs`                                                                                                                                                                         | Same `IFileProvider`; hides symlinked entries from the static-file middleware.                             |
| Template Method                | `apps/api/Modules/Messaging/Jobs/EmailJobHandlerBase.cs`; handlers such as `apps/api/Modules/Invitations/Jobs/TenantInvitationEmailJobHandler.cs`                                                                                              | The base owns the transaction and provider contract; subclasses prepare and render.                        |
| Simple Factory (non-GoF)       | `packages/shared-ts/src/lib/logger/index.ts` (`resolveAdapter`); `apps/api/Lib/CursorSortFieldHandlerFactory.cs`                                                                                                                                | A function or static method chooses the concrete type. PublyApp has no GoF Factory Method today.           |
| Chain of Responsibility        | `apps/api/Lib/Filters/SessionAuthFilter.cs`; `apps/api/Lib/Filters/TenantPermissionFilter.cs`                                                                                                                                                  | Each filter checks, then calls `next(context)`; a failure returns early.                                   |
| Command                        | the job payload record plus `apps/api/Infrastructure/Jobs/JobDefinition.cs`; `apps/api/Infrastructure/Jobs/IJobHandler.cs`                                                                                                                      | The payload is the command; `JobDefinition<TPayload>` is its type descriptor, executed by `JobType`.       |
| Observer                       | `apps/front/src/lib/tab-sync/broadcast-sync.ts`                                                                                                                                                                                                | `postBroadcast` publishes, `useBroadcastSync` subscribes; auth/theme/locale sync.                          |
| Null Object (non-GoF)          | `apps/api/Modules/SocialAccounts/Providers/Bluesky/BlueskySocialAdapter.cs` (`NullLogger<BlueskySocialAdapter>.Instance`)                                                                                                                       | The logger fallback sits at construction; call sites never check for null.                                 |
