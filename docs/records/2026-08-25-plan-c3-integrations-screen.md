# C3 — Integrations screen (Lane #642) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Epic C delivery step 3 (spec `docs/superpowers/specs/2026-08-22-epic-c-social-accounts-design.md`, §6 item 3, part of #642 / #630): the Settings → Integrations page — connected-account list (handle, provider, status pill green/orange/grey, last success, "Visible in: all projects" or project names), the Connect Bluesky drawer (identifier + app password + help link, provider refusals shown as-is), Attach-to-projects checklist (none checked = all projects), Reconnect (same drawer, handle prefilled), Disconnect with a consequence-naming confirmation, and the persistent workspace `NeedsReconnect` banner whose Reconnect button renders only for holders of `tenant.socialaccounts.manage`. i18n in both locales, component tests for drawer + banner, one e2e tagged per #1168, permissions-driven visibility, query invalidation after every action, every failure carrying its cause per DESIGN.md error states.

**Architecture:** Front-only slice in `apps/front` (the C2 API lands on `lane/wt-641`; this plan codes against its wire contract, see Assumptions on C2). Server state flows through TanStack Query calling the Kiota-generated client (`packages/client-ts`, regenerated by C2 — never hand-edited). The page reworks the existing honest coming-later placeholder at `apps/front/src/routes/authed/tenant/settings/integrations.tsx` into the real list; drawers reuse the local `src/components/ui/drawer-form.tsx` layer over Base UI; disconnect confirmation reuses `confirm-dialog.tsx`; status pills reuse `badge.variants.ts` tokens. Permission gating reads the session's permission set the same way existing authed surfaces do (verified pattern in Prerequisites). No backend files change in this lane.

**Tech Stack:** React 19, TanStack Start (`ssr:false` authed surfaces), TanStack Query v5, react-i18next (namespaces `settings`, `common`), Base UI primitives via `apps/front/src/components/ui/*`, Tailwind v4 + `cn()` + design tokens, Vitest + Testing Library for component tests, Playwright e2e tagged `@tenant-workspace @642`, Kiota client from `packages/client-ts`.

## Global Constraints

Copied from spec §7 ("Hard repo constraints that apply") as they touch this lane, plus the standing front rules:

- Vertical slice stays under `apps/api/Modules/SocialAccounts` on the C2 branch — **this plan writes zero backend code**; any contract gap is recorded as an assumption, never invented here.
- The app secret (Bluesky app password) is never returned by any API, never logged, never rendered, never stored in component state beyond the form field lifetime, never in an error message.
- Errors shown as-is with their cause: `credentials_refused` / account-not-found / `provider_unreachable` map to plain-words copy that names what went wrong (DESIGN.md error states; owner rule "transparent failure causes"). No generic "something went wrong".
- Only `401` triggers centralized logout; `403` never logs out — a view-less user gets the Integrations nav hidden, and a denied action surfaces the problem detail message without logout.
- URL/query parameter names snake_case; JSON fields camelCase; no collapsed lowercase wire values (`needs_reconnect`, never `needsreconnect`).
- i18n keys added to **both** locales: `apps/front/src/i18n/locales/en/settings.json` AND `apps/front/src/i18n/locales/fr/settings.json` (+ `common.json` only if a shared key is genuinely cross-page). Missing fr key = failing gate (`check:i18n` parity in CI).
- Design-token discipline is machine-checked (`pnpm --filter front check:design-system` runs inside tests): status pills use the existing `Badge` variants; no raw hex; every z-index utility through the `--publy-z-*` scale; dark mode via tokens only.
- Lint hard rules: no `Array.reduce`, no IIFEs, arrow-function components only (`publy/arrow-function-components` at error), no direct dayjs imports in components, specific-lodash imports, no `console.*` in source, no manual translation of `response-message` keys at call sites (`getFailureMessage(toApiFailure(error), ...)` only).
- React Doctor HARD gate: `just react-doctor` clean in every file this plan touches before each push.
- Forms go through React Hook Form + Zod via the front field wrappers; the drawer form follows the `drawer-form.test.tsx` patterns.
- Loading/empty/error states use `state-surface.tsx` / `skeleton.tsx` — never ad-hoc conditionals.
- The e2e fakes Bluesky (never the real network) and is tagged `@tenant-workspace @642` per the #1168 vocabulary; it lives with the other tenant e2e specs and runs only in the e2e suite, not `just ci`.
- Secrets never in output; never spawn sub-agents; commit early, push after every commit; never touch develop.

## Prerequisites & Assumptions on C2

C2 (`origin/lane/wt-641`, plan `docs/superpowers/plans/2026-08-25-c2-bluesky-connect.md`) is IN FLIGHT and unmerged. Every C2 symbol below was read from that branch with `git show` and is cited with it. **Verified on `origin/lane/wt-641`:**

- Permissions exist and are seeded by C2: class `PublyApp.Api.Modules.SocialAccounts.Permissions.SocialAccountPermissionsForTenant` exposing `VIEW` / `MANAGE` / `PUBLISH` with keys `tenant.socialaccounts.view|manage|publish` (`apps/api/Modules/SocialAccounts/Permissions/SocialAccountPermissionsForTenant.cs`, branch named above). Tenant admins hold them implicitly (spec §1 decision 5).
- Routes (C2 plan §Task 4 route table, branch `origin/lane/wt-641`):
  - `GET /social-accounts` → `CursorPaginatedResult<SocialAccountListItem>` (view)
  - `POST /social-accounts/connect` → 201, `SocialAccountCreated{item}` (manage, rate bucket `SocialConnect`)
  - `POST /social-accounts/{id}/reconnect` → 200 `ApiResponse` (manage, `SocialConnect`)
  - `POST /social-accounts/{id}/disconnect` → 200 `ApiResponse` (manage)
  - `PUT /social-accounts/{id}/projects` → 200 `ApiResponse` (manage; replace-all attach/detach)
- Error contract from C2's plan: 422 validation problems carry `errors` keyed `credentials_refused`; 503 `provider_unreachable`; 409 `already_connected`; 404 for foreign/unknown/revoked-on-reconnect.
- Wire status strings come from `SocialAccountWire.FormatStatus`: `active` | `needs_reconnect` | `revoked` (C2 plan Global Constraints §6).
- Session-open seam `ISocialSessionProvider.OpenSessionAsync(Guid socialAccountId, CancellationToken)` with typed results `Opened | AccountFailure(Cause) | Transient(Cause)` exists (`apps/api/Modules/SocialAccounts/Services/ISocialSessionProvider.cs`, branch named above) — the banner copy and error mapping align with its sanitised cause phrases.
- Test fake `FakeBlueskyClient` (`apps/api/Lib/Testing/Fakes/FakeBlueskyClient.cs`, branch named above) backs API integration specs; the C3 e2e needs its own browser-level fake (open question below).
