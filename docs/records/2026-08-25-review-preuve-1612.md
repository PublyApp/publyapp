## 1. Prove the guard RED — front side (new adversarial reintroduction)

The reintroduction is deliberately **adversarial**: not the `export *` caricature shim already covered by the existing test, but a **named single-symbol re-export**
(`export { shouldLogoutForFailure } from '@org/shared-ts/lib/...'`) inside a plausible convenience barrel (`src/lib/should-logout.ts`) — exactly what a developer adds without thinking.

```text
$ cat > apps/front/src/lib/should-logout.ts <<'EOF'
// Convenience barrel for a couple of shared helpers used across the staff surface.
export { shouldLogoutForFailure } from '@org/shared-ts/lib/should-logout-for-failure';
EOF

$ node scripts/guards/check-shared-ts-import-paths.mts
Dual-path violation: a shared-ts module is re-exported from apps/front/src, creating a second import path (#1533).
  lib/should-logout.ts:2  export { shouldLogoutForFailure } from '@org/shared-ts/lib/should-logout-for-failure';
exit=1
```

**State: RED** (exit 1). The guard names the file, line, and exact text.

Then removal and back to GREEN:

```text
$ rm apps/front/src/lib/should-logout.ts

$ node scripts/guards/check-shared-ts-import-paths.mts
No shared-ts module is re-exported from apps/front/src [OK]
exit=0
```

**State: GREEN** (exit 0). `git status` empty (reintroduction removed).

## What is proven / not proven

Proven:
- The guard detects a front-side reintroduction (shim `export *` AND named single-symbol re-export) — RED→GREEN (§1, test `RED: ...`).
- The extension detects a reintroduction inside `packages/shared-ts/src` — RED→GREEN (§3, test `RED: a shared-ts-internal re-export ...`).
- No false positives on the real tree after extension (806 files, GREEN); relative internal shared-ts re-exports stay GREEN (§4, test `GREEN: ... relative path`).

Not proven by this work (assumed limits):
- The guard only covers re-exports `export ... from '@org/shared-ts/(lib|utils|validations|types)'`.
  A second path created by a TS alias outside that pattern, or by a build redirect
  outside source (e.g. `tsconfig` paths), is out of scope — it is not the defect
  #1533 targets, and the header documents it.
- CI wiring (`pnpm test` → `test:shared-ts-import-paths`) is unchanged and now runs
  all 10 tests; real CI validation happens on the PR (front-e2e 4/4 via CI,
  per the verification policy: no local e2e stack).
