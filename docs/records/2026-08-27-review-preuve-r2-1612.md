## 1. Ce que R2 change — l'analyse syntaxique

La garde R1 balayait chaque fichier **ligne par ligne** (`readFileSync(...).split('\n')`)
et appliquait une regex `REEXPORT_SHARED_TS`. Toute construction sur plusieurs lignes était
**structurellement invisible**. La forme la plus idiomatique — un réexport nommé réparti
sur plusieurs lignes — passait entièrement au travers :

```ts
export {
  foo,
} from '@org/shared-ts/lib/...';
```

R2 remplace cela par une **analyse syntaxique** via ts-morph (`import { ts } from
'ts-morph'`) : chaque fichier est parsé en un vrai AST, et le gardien visite les nœuds
`ExportDeclaration` (et récursivement tous les nœuds). Cela attrape toutes les formes par
construction, au lieu de les énumérer :

- `export { a, b } from '...'` — mono-ligne **et** multi-ligne ;
- `export type * from '...'` — réexport de types ;
- `export * as ns from '...'` — réexport namespace avec alias ;
- `export * from '...'` — réexport namespace ;
- `export type { a } from '...'` — réexport nommé de types ;
- `import ... from '...'` / `import type ... from '...'` / `import('...')` — **inspectés**
  (la marche voit chaque forme), mais **non signalés** : un import direct — statique ou
  dynamique — est le chemin souhaité, pas un second chemin.

Les seuls nœuds signalés sont les `ExportDeclaration` dont le spécificateur de module
correspond à `@org/shared-ts/(lib|utils|validations|types)` — c'est la seule construction
qui crée réellement un **second** chemin résoluble vers le même module.

## 5. Test de régression — la garde analyse la syntaxe, pas le texte

Le test permanent suivant échouerait si la garde revenait à un balayage ligne par ligne :

```
REGRESSION: guard inspects the AST, not lines — multi-line form must be caught (not blank-line-skipped)
```

Il réintroduit la forme multi-ligne (ligne 12 du test, `MULTILINE_NAMED_SHIM_BODY`) et
exige une trouvaille. Un balayage ligne par ligne ne verrait **jamais** la déclaration
`export {\n foo,\n} from '...'` comme une seule instruction `export ... from '...'` sur une
ligne — il scannerait trois lignes séparées, aucune ne correspondant au motif. Ce test
bloque donc toute régression.

  que #1533 cible, et l'en-tête de la garde le documente.

  inchangé et exécute désormais les 16 tests ; la validation CI réelle se fait sur le PR
